## 配置与数据边界

`VITE_BANGUMI_USER_ID` 默认 `cosine`，可在本地环境配置中换成自己的公开 Bangumi 用户名。公开接口不需要 token，客户端不保存凭证。

请求参数中的 offset/limit 仅用于读取下一批，页面始终留在 `/bangumi`；筛选和加载批次不产生分页 URL。五类媒介数量与当前媒介的状态数量分别按需读取，计数失败不会把已加载条目替换成错误界面。原 Bilibili 适配器、环境示例和开发代理已移除。

所有文章/分类/标签/友链页面仍通过 services 取数。嵌套分类由本地 catalog 定义，父级计数和文章筛选包含子路径；原文章 slug、日期、标签及根分类入口保持可用。

## 保留差异与限制

- 本轮未复制上游插画、个人头像或作者身份。保留既有 Unsplash 头图/封面，头像使用 lucide 图标，原有字体沿用仓库现状；字体完整来源/许可材料尚待补齐。这是结构和交互对齐，不宣称逐像素复刻。
- 终端探测曾返回 HTTP 403，但当前浏览器已成功读取真实列表。外部 API 仍可能受网络、限流或部署跨域策略影响，故保留超时、错误、重试并在目标部署环境复测；没有将 fixture 当作线上兜底数据。
- 上游音乐、系列、全站搜索、多语言、第三方评论、编辑器、复杂 Markdown 渲染及 SEO 预渲染仍未纳入本轮。归档印记筛选依赖上游特有的内容标记数据，本地文章未引入该领域模型。
- 开发服务器深层 URL 可以打开不代表生产托管已配置回退；仍需在目标托管环境验证所有 history 路径刷新。
