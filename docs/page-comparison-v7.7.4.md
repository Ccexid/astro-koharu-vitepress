## 全站共同差距

### 1. 封面与页面身份没有接通（P1）

`src/App.vue:45` 给全部路由渲染 `SiteHero`。`src/app/site-cover.ts` 为动态详情提供的只是通用标题；虽然 `src/composables/usePageCover.ts:5` 有更新封面的控制器，`src/pages` 没有任何调用。浏览器验证结果：

| 路由                       | 当前封面标题 | 正文真实标题     |
| -------------------------- | ------------ | ---------------- |
| `/posts/a-note-for-spring` | 文章         | 给春天留一页空白 |
| `/categories/life`         | 分类文章     | 生活             |
| `/tags/everyday`           | 标签文章     | 日常             |

参考 `src/components/ui/cover/Cover.astro:55` 区分普通封面 60svh 与 compact 封面 42svh（窄屏 36svh）；当前全部页面桌面共用 378px、390px 视口共用 315px。参考文章标题和元信息在封面，当前标题、摘要和元信息集中在封面下的第二个大标题区。普通信息页也容易出现封面和正文标题重复。

建议先接通真实标题/状态和文章元信息，再分别定义首页、文章、信息索引的封面比例与字号。这个改动影响全部页面，比逐页调整卡片颜色更优先。

证据：当前 `src/components/SiteHero.vue:36`、`src/app/site-cover.ts:35`、`src/pages/PostPage.vue:73`；参考 `.reference/v7.7.4/src/components/ui/cover/Cover.astro:55`、`:99`，`src/pages/post/[...slug].astro:198`。

### 2. 阅读布局、侧栏与移动导航（P1）

当前全部页面使用作者信息侧栏。文章页又通过 `src/styles/article.less:88` 划分正文与 160px 目录，使文章阅读区域进一步变窄。参考文章模式使用侧栏承担目录，并能切换个人信息；移动端有专门的章节顶栏与目录入口。

当前抽屉从右侧打开，内容是导航和个人资料；参考左侧抽屉有手势关闭及更丰富的阅读导航。当前原生 `dialog` 已处理基本模态交互，实测打开后聚焦关闭按钮，Escape 关闭后焦点回到打开按钮。这是可保留的基础能力，不应为追求外形而丢掉。

证据：当前 `src/App.vue:50`、`src/pages/PostPage.vue:95`、`src/components/MobileDrawer.vue`、`src/styles/responsive.less:13`；参考 `.reference/v7.7.4/src/components/layout/HomeSider.astro:25`、`src/components/layout/MobilePostHeader/index.tsx:74`、`src/components/layout/MobileDrawer.astro`。

### 3. 壳层构图与视觉系统（P2）

- 参考把主要内容放在带背景/阴影的内容表面中，页脚位于右侧内容列；当前内容区更平，文章卡片单独浮起，页脚横跨整个页面。
- 参考为图片头像、社交入口和可点击统计/导航组织；当前使用“春”字头像、最近更新、分类和标签列表，统计只是文本。
- 顶栏：参考随滚动方向隐藏/显示，当前超过 32px 就固定并变胶囊；参考手机品牌居中，当前品牌靠左。
- 窄屏切换边界不同：参考顶栏/侧栏主要在 992px 左右切换，当前 820px 才收起；文章卡片又在 768px 改为纵向。平板区间的导航和正文密度需要单独比对，两个端点通过不能证明所有中间宽度一致。
- 粉色主题、圆体文字、斜切图文卡、浅/深色切换及 reduced-motion 已存在。当前叶绿辅助色、自然摄影、单层圆弧波浪、字头像与参考插画/多层波形/花瓣装饰构成有意视觉差异。不要把所有差异都归为“没实现”。
- 回顶/阅读进度浮动工具、封面复制链接等细节未对齐；季节装饰、音乐、语言切换等仍应按范围决策。

证据：当前 `src/styles/layout.less`、`src/components/SiteHeader.vue`、`src/components/SiteSidebar.vue`；参考 `.reference/v7.7.4/src/layouts/TwoColumnLayout.astro`、`src/components/layout/Navigator.tsx`、`src/components/ui/cover/Cover.astro`。

### 4. 友链存在实际基础样式遗漏（P1）

`src/pages/FriendsPage.vue:33` 使用 `.friends-grid`，但全项目只有 `src/styles/responsive.less:82` 为它写了窄屏列数，没有 `display:grid`、桌面列数或 `gap`。1440px 浏览器实测：

```text
display: block
grid-template-columns: none
gap: normal
三个链接各宽 868px、高 120px，纵向坐标间隔恰好 120px
```

因此当前不是预期的卡片网格，而是连续整行。参考 `.reference/v7.7.4/src/components/friends/FriendsGrid.astro:70` 有明确的多列和断点规则。应先修基础布局，再讨论分组和卡片效果。

### 5. 字体、素材记录与文档漂移（P2）

当前实际打包 `src/assets/fonts/ChillRoundF.ttf`，`tokens.less` 只声明 400 字重，并设置 `font-synthesis:none`。多处标题请求 600–750，不能假定当前单一字体声明能表现预期的粗细层级。本次生产构建中的字体文件约 6.17MB；这是当前资源体积观察，未测真实网络下的首屏时间。

旧视觉基线仍写“系统衬线/无衬线”和“不下载或复制字体”，与实际实现不符；应用自有文件中也未找到该字体的完整来源/授权记录。应补记录，不能据此直接判定未经授权。图片和品牌素材也不能因为存在上游仓库就直接复制。

README 仍说其他页面未实现、路由拟采用 Vue Router，并把 `/posts/welcome` 当示例文章；实际已使用 Vue Router，该 slug 不在模拟数据中。旧基线里“5 个服务测试”及追番范围描述也已过时。应在后续实施时同步文档，避免以旧验收表替代本次证据。

## 推荐实施顺序

1. 接通封面真实内容；明确首页/文章/信息页的封面比例和标题层级；修复友链基础栅格。
2. 调整文章为目录侧栏的阅读布局，补当前章节反馈与移动目录；保留现有焦点管理和数据状态。
3. 分类改为层级目录；分类/标签详情共用紧凑时间行；标签总览单独做频次与折叠表达。
4. 首页拆置顶与普通文章、补精选分类；明确选择保留滚动追加还是改页码分页，再统一列表行为。
5. 归档补日历和年月跳转；友链补分组/头像/申请信息；完善关于与 404。
6. 最后对齐平板断点、主题令牌、页脚、波形和细节动效，并以本次指定版本重新保存同视口截图。

追番单列决策：保留 Bilibili 和现有字段，只借鉴海报墙布局；或另行明确改为 Bangumi。当前任务只记录差异，不替用户选择或改数据源。

## 不计入本次必补差距的能力

- 全站搜索、系列/周刊、音乐、多语言、第三方评论，仍是可选项；上游组件出现也不代表对应服务默认可用。
- 评论需要 provider 配置；相关文章依赖相似度数据；子分类筛选依赖 children；友链分组依赖 groups；Bangumi 页面依赖启用配置。报告已按实际配置和条件分别描述。
- Astro/React、Markdown/MDX 解析、CMS/编辑器、数据库、认证、后端、RSS/sitemap、文章预渲染不属于 Vue 模板的差距修复范围。
- 上游的个人资料和文章内容不应照搬。继续使用合理的演示数据，并保持 pages → services → data 的边界。
